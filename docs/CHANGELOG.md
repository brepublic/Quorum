# 更新日志

## 2026-10-01：媒体席位与程序性投票权限

- 新增“媒体代表”，默认关闭表决权和程序性投票权限；媒体代表只能上传新闻及即时消息，代表文件入口和登录后的上传入口均在服务端校验，保留其他文件的阅读权限。
- 席位及委员会模板增加“程序性投票”设置，仅允许两项权限均开启、仅程序性权限开启或均关闭；表决权开启时程序性投票锁定开启并显示淡蓝色，程序性投票关闭时表决权锁定关闭并显示灰色。现有席位及模板默认保留程序性权限。
- 无程序性权限席位始终视为出席，但不进入点名，不计入出席数及法定人数，也不能参与发言、问题、动议提出及附议等会场程序；意向性投票仍允许所有出席席位参与。
- “出席”和法定人数按程序性权限计算，右上角显示程序性出席、三分之二多数和简单多数；点名结束后，实际出席中存在有程序性权限但无表决权的席位时，分别显示表决与程序的多数。
- 程序性动议及表决按程序性出席计算，实质性表决按有投票权的出席计算；文件表决页将人数标签改为“有投票权”，保留忽略弃权的三分之二多数规则，移除“包含无表决权席位”开关。
- 代表文件页按席位类型分组选择国家，组名加粗且不可选，成员不缩进且保持正常字重，隐藏没有有效出席成员的组；搜索结果保留所属组名。
- 席位页表头及下拉框文字保持单行，调整列宽，过长的下拉框文字显示省略号。
- 类型检查、构建及相关前端和真实 PostgreSQL 回归通过；浏览器验收覆盖权限联动、分组与搜索、媒体上传类型、点名多数、表决人数，以及桌面、平板和手机布局。
