# 更新日志

## 2026-09-30：危机组、危机更新与指令联动

- 新增固定编号的危机组 X.Y 与更新卡片 X.Y.Z，分别在会期和组内连续分配；每组最多一张未发布卡片，准备更新不覆盖正在处理的版本。卡片按更新编号倒序展示，发布后锁定内容。
- 导航调整为“有主持核心磋商 → 危机 → 指令 → 决议 → 表决 → 意向性投票”。危机入口和待处理组红黑各闪烁一秒，少于五分钟显示橙点、到时显示红点，汇总以红点优先；桌面、“更多”和侧栏共用当前委员会的提醒，结束后清除。
- 危机通告仅允许主席上传，记录系统名称与原始上传名称；归属只解析系统名称。零个、一个和多个活跃组分别建议完整新组编号、该组下一更新编号和待补全的会期前缀。名称编辑时禁用“危机 →”，失焦保存并校验后恢复，手动名称不会被自动建议覆盖。
- 通告审核保留下载与“危机 →”，普通批准、驳回及文件发布接口均不能绕过危机发布。导入校验会期、连续编号、唯一未发布卡片和已结束组；重复导入跳转已有卡片。冲突可修正系统名称，或确认替换未发布通告，保留卡片编号、标题和处理时间，原文件仍待审核。
- 发布在同一事务批准并公开通告、设为待处理、覆盖旧卡片、使旧版本未完成指令失效，并重设计时器及自动启动计划；失败全部回滚，重复请求不重设计时。正在表决的旧指令显示“危机已更新”和“未通过”，保留已保存选票并清除未提交选票的提交资格；已完成结果保留历史。
- 各组使用独立后台计时，切换页面、关闭浏览器或服务重启均不重置。委员会自动开始延迟默认五分钟，零立即开始、负数不自动开始；等待时间与处理时间分开计算，首次手动开始取消计划，主动暂停后不自动恢复。现有服务进程处理计划，归档委员会不参与自动启动，无新增部署服务或依赖。到时仍为待处理。
- 指令在开始表决前必须关联待处理危机及其版本，跨会期可应对原编号危机；禁止新增修正案，默认三分之二多数且弃权计入全部出席有表决权席位的分母。完整结果保存成功并通过后结束组内全部卡片，更正后恢复结束前状态、保持计时暂停；其他有效通过指令仍可维持结束，旧版本已完成结果的更正不结束当前版本。
- 委员会有未结束危机时，点击暂停先列出危机并询问“结束全部危机并暂停委员会？”。确认在同一事务结束全部未结束组并暂停，取消保持原状；未发布卡片结束时，其通告仍待审核且未公开。
- schema 78 将危机、指令关联、自动启动设置与计划纳入现有权限、版本检查、重复请求、实时事件、审计、归档和委员会删除流程，保留既有历史。同步修正原有回归中缺少文件分类和已读文件编号的测试输入。
- 验收通过：完整非数据库回归 737 项、真实 PostgreSQL 回归 154 项、归档自动启动专项及生产构建。真实浏览器覆盖上传与系统名称、焦点禁用、跳号修正、通告替换、更新使表决失效、指令通过与改票恢复、暂停取消与确认，以及桌面、更多菜单、390px 和 320px 布局、闪烁、圆点与提醒清除；实际服务重启确认计时基准与取消的自动启动计划保持不变。
