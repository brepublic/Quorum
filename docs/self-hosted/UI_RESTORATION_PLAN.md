# 自托管界面与交互恢复计划

## 目标

以 `master@681e481` 的成熟会议操作流程、页面信息架构和高密度桌面布局为交互基线，重建 `fix@fdd1a06` 的浏览器界面。浏览器仍只调用同源自托管 API/SSE；PostgreSQL、revision、幂等、权限、审计、规则包、文件 provider、Chair Agent、归档删除和运维功能不降级。

旧版源码只作为行为和布局参照。不得复制 Firebase import、path write、客户端 actor 推导、匿名浏览器身份或旧计时状态模型。

## 不可破坏边界

- 单一生产路径保持为 React → 同源 HTTP API/SSE → Node 模块化单体 → PostgreSQL。
- 一个委员会最多一条 SSE；快照、事件缺口恢复和 `OFFLINE_READONLY` 行为保持不变。
- 所有写入继续使用意图明确的命令，由服务端推导 actor，并执行权限、revision、事务、事件与审计。
- 保留系统管理员、Owner、Chair、member 和匿名公开访问者的现有能力边界。
- 保留规则包驱动的阶段、点名回答、动议、表决、发言、让渡和文件状态。
- 保留模板、S3、Chair Agent、运维、归档、导出、永久删除和账号处置等新增功能。
- 每个切片完成后运行针对性测试、`git diff --check`、`pnpm build:self-host` 和 `pnpm verify:no-legacy-runtime`；真实 PostgreSQL 与浏览器验收单独记录。
