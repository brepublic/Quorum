# 决议草案介绍、表决创建与旧数据修复

## 正常流程

1. 草案先处于“待介绍”，可以填写正文或选择委员会内已发布的内容文件。
2. “介绍决议草案”下拉框显示待介绍草案。空正文（含纯空白）且没有内容文件的选项显示“无内容”并禁用；待介绍草案显示“未介绍”。有内容的待介绍草案可提出介绍动议。
3. 介绍动议通过前，服务端再次检查当前正文和关联文件；通过后草案为“已介绍”，仍可编辑。
4. “对决议草案投票”下拉框列出待介绍和已介绍草案。空草案禁用；未介绍草案显示“未介绍”并禁用。已有“未讨论”提示继续保留。
5. 投票动议通过时，服务端在同一个事务中检查目标状态、正文、关联文件、开放会期和合格投票席位，创建文书直接表决、冻结当前版本、写入“正在表决”，最后保存动议通过状态、文书历史、事件及审计。
6. 成功后直接打开该草案的表决页，不再经过新建表决确认。完成表决和更正结果继续同步文书的通过／未通过状态。

正文、文件或投票资格检查失败时，上述事务全部撤销：动议维持原状态，草案没有新增冻结或表决。若通过来自动议的正式表决结果公布，公布也在同一事务内；失败时选票和已关闭的动议表决保留，可修正草案后再次公布。

“文件已发布”是文件系统的审核／可用状态；“草案已介绍”是议事状态。草案选择器中的“未介绍”表示后者。文件引用可能在绑定后被删除或变得不可用，因此服务端仍复核引用。

## 其他现有入口

- 主席手工创建直接表决沿用现有资格和权限；创建成功才冻结草案并更新状态。现有直接对待介绍草案创建表决的主席入口保留，数据库允许普通决议草案从待介绍进入正在表决。
- 旧逐席录票和整批提交接口若首次开始普通决议草案表决，复用同一创建检查，不能绕过正文和版本冻结。
- 旧文书 `RECOMMEND_BALLOT` 命令只记录建议，不提前冻结普通决议草案；正式表决接口在实际创建时冻结正文并记录所用规则，公布结果继续读取该历史。
- 修正案和指令的表决流程保留。本次自动创建联动及状态修复针对普通决议草案。

## schema 83 迁移流程

迁移由正常部署启动执行，整个脚本在一个事务内运行。先按日常命令的顺序锁定委员会、文书，短暂阻止并发写入，再仅在该事务内停用文书状态触发器以修复旧数据。完成后重新启用原有版本不可变保护；任何步骤失败都会回滚，包括触发器状态。

解除冻结的记录必须同时满足：

- 未删除的普通决议草案，文书状态为 `VOTING`；
- 没有直接表决开始或完成时间；
- 没有任何正式表决；
- 没有任何当前或已撤销的文书选票、选票历史、结果决定。

这些草案恢复为 `PUBLISHED`（已介绍），清除表决版本引用，并递增文书版本号。保留正文版本、历史动议及文书操作，不自动重放旧的通过动议或补建表决。恢复后可以填写内容，再提出新的投票动议或由主席手工创建表决。

已有真实表决但文书仍为待介绍／已介绍的普通草案补正为 `VOTING` 并补齐冻结版本。已有终态、指令、修正案和已删除记录不参与修复；已进入表决的有记录草案不会被解锁。每笔修复追加委员会事件和系统迁移审计（`migration:0083`），记录前后状态、版本号及冻结版本。修复条件在成功后不再满足，重复执行不会重复修复或追加审计。

## 验收

- 页面：空草案禁用、灰色“无内容”、未介绍提示、鼠标及键盘不能选择禁用项、中英文、关联文件草案仍可选。
- 服务端：空内容和纯空白拒绝；动议提出后清空正文仍拒绝通过；无合格投票席位不产生部分通过或冻结；通过后立即存在真实表决；重复及并发通过最多创建一份。
- 状态：手工创建、旧录票入口、正式表决创建及结果公布与文书一致；修正案、指令原有回归通过。
- 迁移：孤立冻结恢复编辑，有真实表决／选票历史／终态／指令／已删除记录保持原样，重复执行无重复修复，真实表决版本仍不可清除。
