## 1 目标和交付范围

让第一次使用软件的人无需理解配对码、私有配置路径或同步进程，也能完成连接；让已连接的用户一眼看清委员会、文件位置和同步状态。

主流程固定为：

**首次确认 Quorum 网址并登录 → 选择委员会 → 确认存储文件夹 → 自动配对并启动同步。**

以后启动恢复已保存的设备连接和原存储目录，直接进入同步主页。账号登录服务于首次连接和需要重新授权的操作，日常同步使用现有设备凭据。

交付覆盖以下部分：

- 当前 Linux 桌面版，沿用 Rust 与 Slint 原生窗口，以及 TypeScript 与 Node 同步核心。
- 一个窗口管理一个委员会、一个 Agent 实例。
- 网页存储设置的按钮组织、配对快捷入口、下载配对文件和反馈。
- 原生登录、委员会选择、目录确认、同步主页、连接与存储设置、语言入口和独立诊断页。
- 服务端按权限返回可连接委员会，复用现有账号、配对和存储规则。
- 本地网址偏好、启动恢复、每个委员会独立递增的默认目录。
- Linux 应用图标、桌面入口、窗口身份及文件和链接关联。
- 功能测试、真实 Linux 交互验收、文档和 CHANGELOG。

## 3 Quorum 网址和本地持久化

### 3.1 网址偏好

- 全局的含义是当前 Linux 用户的 Agent 应用偏好，跨应用重启和委员会连接保存。
- 新安装默认网址为 `https://quorum.sramun.org`。
- 首次启动在登录页直接显示预填的网址，用户可修改；网址、邮箱、密码属于同一登录任务。
- 沿用 `$XDG_CONFIG_HOME/quorum-agent/`；未设置该环境变量时使用 `~/.config/quorum-agent/`。可以扩展现有桌面偏好文件，避免重复维护同一偏好。
- 现有安装优先读取有效连接中的服务器地址，避免升级后把原站点替换为默认网址。
- 设置页提供修改入口；用户输入域名时可规范化为 HTTPS 地址，界面显示实际将连接的站点。
- 网址应经过格式和服务可达性检查，错误显示在对应位置，并保留用户输入。

### 3.2 修改站点

网址偏好与已绑定设备记录中的服务器地址具有不同用途：前者用于登录和建立连接，后者决定既有设备凭据的接收方。

修改网站地址后，旧账号登录状态必须清除。已有设备绑定不能只替换网址后继续向新站点发送原凭据；切换当前连接应进入重新连接流程。界面应显示当前实际连接站点，并清楚表达更改的后果。

### 3.3 账号和设备信息

- 长期保存网址、应用语言、既有连接恢复信息和目录编号。
- 账号密码不落盘，不写入日志、错误详情或配置文件。
- 账号的临时登录状态用于读取候选委员会和授权配对；配对完成后清除，并通过既有退出能力结束这次登录。
- 长期同步继续使用现有设备凭据和私有配置保护方式。
- 私有配置目录和文件沿用现有用户权限及原子写入规则；普通用户流程中自动管理配置文件的位置。
- 配对文件承载短期授权；现有设备私有配置承载长期连接信息。两者在校验、权限和界面名称上保持清晰区别。

## 4 应用页面和导航

页面按照当前连接阶段互斥显示。菜单只提供在当前阶段有意义的入口。

| 页面 | 进入条件 | 用户当前任务 | 主要操作 |
| --- | --- | --- | --- |
| 登录 | 没有可恢复连接，需要原生授权 | 确认站点并验证账号 | 登录 |
| 修改初始密码 | 登录结果要求修改临时密码 | 完成账号要求 | 保存新密码并继续 |
| 选择委员会 | 登录有效 | 选择有权连接的委员会 | 选择后继续 |
| 确认存储位置 | 已选委员会，或收到有效网页配对信息 | 确认委员会和文件夹 | 连接并开始同步 |
| 同步主页 | 已建立并加载有效设备连接 | 查看状态与文件，控制同步 | 按状态显示开始或停止同步 |
| 连接与存储 | 从应用菜单进入 | 查看当前连接，按需编辑 | 停止同步并编辑，或编辑设置 |
| 诊断日志 | 从菜单或相关错误入口进入 | 查看、复制或导出诊断信息 | 当前诊断任务对应操作 |

页面顶部保持简洁的应用身份和菜单，中文名称为 `Quorum 主席 Agent`，英文名称为 `Quorum Chair Agent`。设置和诊断页有明确的返回入口。首次连接期间主要空间用于当前步骤；文件列表和同步控制属于同步主页。

应用关闭沿用现有进程生命周期：先结束同步，再退出。存在未保存修改时，明确处理用户草稿。

## 5 原生登录交互

### 5.1 登录页结构

从上到下排列：应用名称和图标、当前任务标题、Quorum 网址、邮箱、密码、登录按钮。登录页底部提供低强调的 `Language / 语言` 及备用连接方式。

网址默认已填写。每个输入框有常驻标签，标签不能只靠占位文字。密码默认遮蔽，提供显示／隐藏切换；新密码页预先展示 12–256 字符规则，登录不套用新密码规则；提交中显示进度，防止重复提交。网站可达但账号错误、无法连接网站、证书问题和服务返回异常应区分反馈。

通过现有原生控件完成输入，通过现有 Node 桥接执行 HTTPS 请求，复用现有身份验证规则。页面层只接收完成当前交互所需的结果和可公开展示的错误。

### 5.2 登录结果

- 登录成功且账号可用：加载委员会列表。
- 必须修改初始密码：显示原生修改密码页面，成功后继续加载列表。
- 邮箱或密码错误：提示贴近对应字段并聚焦；网站、邮箱与密码均保留以便修改。证书、网络、服务器错误也保留密码供重试；成功登录／修改密码或离开登录流程时清空密码并恢复遮蔽。
- 登录受限、账号不可用：按服务器现有错误语义提示可采取的下一步。
- 服务器证书未被系统信任：在登录错误附近提供现有服务器证书选择入口，完成配置后重试；该入口必须在登录阶段可用，不能等到登录成功后的目录页面才出现。
- 登录过期：返回登录步骤，保留仍可复用的非秘密选择；重新登录后重新验证委员会状态。
- 列表请求失败：显示重试，不能用“没有委员会”代替加载错误。

在需要返回或更换账号时，清理本次临时登录状态。语言切换重译界面和错误，不重新创建整个表单或丢失普通输入。

## 6 委员会选择和暂停提醒

### 6.1 列表内容与权限

服务端返回当前账号有权管理的委员会及连接所需的状态。列表行以委员会名称为主，辅以现有会议名称或议题等识别信息，展示委员会状态和当前存储或设备状态。

“所有可绑定委员会”是当前账号有权绑定的集合。公开可浏览权限不能替代主席或所有者权限；系统管理员身份本身也不是委员会绑定权限。

| 委员会情况 | 列表和操作规则 |
| --- | --- |
| 用户是主席或所有者，委员会活动且无其他当前设备 | 可选择并进入目录确认 |
| 用户是主席或所有者，委员会暂停 | 可选择，但必须按下述规则显示暂停并提醒 |
| 委员会已绑定其他电脑 | 显示当前电脑名称和已绑定状态，使用明确的更换电脑流程 |
| 普通成员或无管理权限 | 不作为可连接候选 |
| 已归档或正在删除 | 不作为可连接候选 |
| 已有服务器或 S3 存储 | 显示实际存储方式，保留既有存储配置 |

列表加载、无结果、请求失败分别呈现。没有可连接委员会时说明当前账号没有可连接项目，并提供重试或返回登录的明确动作。列表内容较多时提供搜索，不能把加载失败表现成搜索无结果。

### 6.2 暂停委员会的明确要求

这是用户最后补充确认的要求：**委员会暂停时必须标明，并提醒用户。**

- 列表行显示可读文字 `已暂停`，辅以警示色或图标；不能只靠颜色区分。
- 选中暂停的委员会后，在选择详情或下一步确认区域显示提醒。
- 最终确认存储位置时，仍能看到该委员会处于暂停状态。
- 提醒表达的含义固定为：`委员会已暂停，本地文件变更将在恢复后同步。`
- 暂停提醒不阻止有权限用户绑定，也不把委员会暂停误报为网络离线或 Agent 已停止。
- 绑定后的主页应在委员会身份区域保留相应状态提示，与同步运行状态分开表达。
- 暂停状态变化后，按实际可取得的最新服务端状态更新显示；旧状态不能继续作为当前状态无条件呈现。
- 中英文均需有完整提示。英文表达同一含义，例如 `This committee is paused. Local file changes will sync when it resumes.`

### 6.3 已有主席电脑

选择行本身不会撤销另一台设备。界面显示当前电脑名称，通过明确的 `更换主席电脑` 操作说明并确认将撤销旧设备的当前授权，再进入现有转移配对流程。

列表只是选择时的快照。最终提交必须重新检查委员会权限、可写状态、当前设备和版本；状态变化时刷新并让用户重新判断，不能把初次配对失败自动改为设备接管。

## 7 存储目录确认和自动配对

### 7.1 页面组织

上方是委员会名称、Quorum 网站和有关当前状态的提示；中间是 `存储文件夹` 标签、可选择复制的路径文字以及紧邻的 `选择文件夹…`；下方是折叠的其他设置和统一的操作区。

其他设置按需包含电脑名称和服务器证书。私有配置文件路径由应用管理，不属于首次连接需要理解或填写的内容。

目录通过系统文件夹选择器选择。关闭选择器或取消选择保留之前的路径。已知路径按普通信息展示，不能以无标签的空白输入框代替。

### 7.2 默认目录和编号

- 使用当前系统用户的 Documents 目录；优先尊重系统的 Documents 位置配置。
- 默认根位置为 Documents 下的 `Quorum` 文件夹。
- 委员会子目录使用 `委员会名称-编号`。
- 每个委员会独立递增，例如 `安理会-1`、`大会-1`、再次建立安理会的新目录时为 `安理会-2`。
- 本地计数沿用服务器和委员会稳定标识，展示目录使用委员会名称；目录名中的不合法路径字符沿用现有处理。
- 只进入确认页面、返回上一步或取消选择时，不实际创建目录、不消耗编号。
- 真正确认并分配目录时独占创建，避免覆盖已有目录。失败重试应识别本次已经分配的目录，不因每次重试不断新建编号目录。
- 后续正常启动恢复原目录，不重新分配编号。
- 原目录缺失或无法访问时显示恢复措施，不能悄悄创建另一个空目录并表示同步正常。
- 新配对使用满足现有安全校验的目录；恢复已有连接则校验原目录的设备身份及元数据。

### 7.3 确认操作

普通首次连接的主要按钮为 `连接并开始同步`。用户最后确认后，自动完成必要的授权、配对、私有配置保存及启动，成功进入同步主页。等待过程显示明确阶段，提交期间抑制重复操作。

原生登录入口内部生成和使用短期配对授权，普通用户不需要查看或复制。网页唤起和配对文件入口使用收到的短期授权，但同样进入该目录确认页面。

失败后保留委员会、目录和可复用选项。区别对待尚未配对、配对已完成但本地保存或启动失败，以及请求超时导致结果暂时无法确认等情况；不能统一显示为“未连接”后立即重复接管。

### 7.4 存储启用规则

- 委员会没有活动存储配置时：配对成功同次事务自动启用主席电脑存储。
- 委员会已有存储配置时：保留原存储配置。
- 已有服务器或 S3 存储的委员会，配对成功不代表主席电脑已经成为当前文件存储。确认页、按钮含义和完成状态都应准确表达实际结果。
- 网页入口与原生入口使用同一业务规则。并发情况由服务端在提交时重查。

## 8 同步主页交互

### 8.1 主要信息

页面标题使用当前委员会名称。身份区域显示实际站点及需要用户注意的委员会状态；同步区域显示连接是否健康、是否正在同步、当前任务和必要的更新时间。

同步控制按当前状态只提供有意义的动作：运行时 `停止同步`，已停止时 `开始同步`。启动中、停止中有进度与明确状态，不能允许重复触发相互冲突的操作。

文件夹入口与存储位置放在一起。用户可以打开本地文件夹；路径是有标签、可复制的信息。委员会网页作为已连接后的辅助入口放在菜单或相关操作中。

### 8.2 文件列表

- 展示文件名、大小、本机状态、服务器缓存状态；相关状态保持独立。
- 传输进度放在相关文件行中，仅在有真实传输时显示。
- 达到 100% 仍需实际校验及落盘或提交完成后，才能显示已完成。
- 搜索和已删除文件筛选位于文件列表工具区。
- 文件名和路径较长时可换行或在适当位置截断并提供完整查看方式，不挤掉状态和必要按钮。
- 删除、审核、发布和冲突状态沿用现有业务语义。界面调整不改变实际文件操作规则。

### 8.3 必须分别表达的状态

| 状态 | 用户应看到的反馈 |
| --- | --- |
| 首次加载文件状态 | 正在读取或连接，不能提前显示没有文件 |
| 委员会尚无文件 | 清晰空状态与相关下一步动作 |
| 搜索无结果 | 搜索无匹配项，可清除筛选 |
| 同步运行且连接健康 | 真实当前状态与文件任务 |
| 用户已停止同步 | 明确已停止，不继续显示正在接收或上传 |
| 暂时离线 | 正在重试，旧文件状态有更新时间或过期提示 |
| 服务器缓存不可确认 | 标记未知，不能沿用旧绿色状态冒充当前可用 |
| 单个文件失败或冲突 | 在相关文件行给出原因和适当处理入口 |
| 已配对但未作为委员会当前存储 | 明确实际存储状态，不显示虚假的同步启用成功 |

委员会暂停、网络连接中断和用户停止同步是三个不同状态。它们可以同时存在，必须分别呈现。

## 9 连接与存储设置

设置从应用菜单进入，使用独立页面，有明确返回同步的入口。默认展示当前配置摘要，查看本身不停止同步。

| 分组 | 内容与相邻操作 |
| --- | --- |
| 委员会连接 | 委员会、当前站点、电脑名称、站点修改入口 |
| 本地存储 | 当前目录、打开文件夹、适当的目录维护入口 |
| 高级设置中的网络连接 | CA 证书选择及当前有效值 |
| 高级设置中的文件扫描 | 完整扫描间隔及单位 |
| 高级设置中的维护操作 | 重新定位已移动的文件夹、连接文件另存为 |
| 更换委员会／解除连接 | 当前连接摘要下方；菜单提供更换委员会快捷入口 |

### 9.1 编辑和保存

- 运行时进入设置先只读；修改入口为 `停止同步并编辑`。
- 原本已停止时使用 `编辑设置`。
- 确认同步已停止后进入可编辑状态。
- 原本运行中的连接，页尾为 `取消并恢复同步`、`保存并恢复同步`。
- 原本已停止的连接，页尾为 `取消`、`保存`，完成后保持停止。
- 保存成功后才使用新配置；保存失败保留表单并定位错误。
- 取消恢复已保存值；恢复同步是否成功应单独反馈，不能把保存成功当作启动成功。
- 只有实际存在未保存修改时，离开或关闭才出现草稿处理确认。
- 切换语言、展开高级设置等操作保留正在编辑的内容。

### 9.2 目录维护

沿用“用户先搬迁完整文件夹，Agent 再重新定位”的流程。按钮表达为 `重新定位已移动的文件夹…`，选择后检查原设备身份与目录元数据，通过后保存路径。

### 9.3 连接文件维护

已有私有配置通过登录页的 `更多连接方式 → 打开配对或连接文件…` 恢复；与短期配对文件共用选择器，避免重复入口。恢复保留同一设备身份、原目录和恢复记录。

高级维护保留 `连接文件另存为…`。沿用现有另存后使用目标文件的行为；覆盖已有目标时明确确认，并保持私有权限。该操作的名称和反馈必须对应实际另存语义。

### 9.4 解除连接

解除连接与普通保存分开，使用明确确认。运行中也可发起；确认后自动停止同步，等待清理与目录解锁，再撤销当前设备授权。成功后返回登录页。更换委员会另走先选择后提交的流程：登录、选择目标和目录时保留原同步，最终确认列出来源与目标；先验证目标设置、目录和证书，再停止原同步、撤销旧授权并配对新委员会。取消选择或撤权失败可返回原连接；旧授权已撤销后的新配对失败明确提示阶段，保留目标供重试／重新选择。两个服务端操作不具备原子切换或自动回滚保证。确认框默认焦点为取消，最终撤权使用危险样式。沿用现有服务端撤销当前设备和本机清除身份的机制。

无法完成服务端撤销时，若用户使用现有“仅解除本机绑定”能力，必须明确这是本机结果；原服务器授权尚未确认撤销。保留原数据及配置文件，清除自动恢复指针的行为应与既有实现一致。

## 10 语言和诊断

首次使用优先采用系统语言，之后使用记住的选择。首次登录页底部的入口固定为 `Language / 语言`；日常使用时移入应用菜单，仍使用双语名称。选项采用语言自己的名称，如 `English`、`简体中文`。

语言改变只影响界面文案，不改变委员会名称、文件名、目录、设备身份及正在编辑的普通表单。错误以结构化状态保存，在切换时重新翻译。

诊断日志使用独立页面，通过菜单或相关错误进入。提供既有日志查看、筛选、复制和脱敏导出能力；显示时间和必要事件，秘密、密码、账号登录凭据及设备授权不得出现在诊断内容中。“重新启动同步”放在同步页的次级菜单，按当前进程状态启用。

## 11 网页端配套变化

位置沿用委员会的 `文件 → 存储设置`，保持现有路由。

- 当前存储摘要与相关操作放在同一行或同一内容块；空间不足时自然换行，不能为单个普通按钮固定预留整行。
- `配对主席电脑` 保留为从网页发起的快捷入口。已存在另一台电脑时对应明确的更换操作和确认。
- 生成短期授权后尝试通过现有专用链接唤起 Agent。
- 下载入口统一使用 `下载配对文件`，作为备用方式；Agent 对应 `选择配对文件…`。
- 等待 Agent、已过期、已配对、唤起未完成分别反馈。发起了链接跳转不等于 Agent 已打开或配对成功。
- 实际配对成功以服务端绑定状态为准，网页及时刷新，不能要求用户凭是否弹窗判断。
- 网页唤起与导入文件均进入原生目录确认流程，有效授权已包含委员会信息时无需再让用户在 Agent 登录并重新选择同一委员会。
- 备用入口说明获取位置和文件用途，只保留完成任务需要的短文案。
- 手动配对码和已有连接恢复保留在低频的更多连接方式中。
- 没有活动存储时自动启用主席电脑，已有存储保持原状；网页与 Agent 展示一致。

## 12 样式设计

整体沿用已采纳原型的简洁桌面风格：紧凑应用栏、清晰页面标题、适度留白、浅边框、稳定的操作位置。网页继续使用已有网页组件体系，原生页面使用现有 Slint 组件能力实现同样的信息层级。

### 12.1 版式和操作层级

- 登录页使用居中的窄内容区；委员会选择、目录确认、设置使用适中的表单宽度；同步页把较多空间留给文件列表。
- 宽窗口中的表单不会横向拉满；高度增加时也不会把提示和主要按钮推到离主体很远的位置。
- 顶部只承担应用身份与菜单。页面标题与页面动作属于各自内容区域。
- 每个步骤只有一个主要动作；蓝色实底用于当前主要动作，次要操作采用浅边框或低强调文字按钮。
- 取消和提交同处表单末尾；目录、证书等选择按钮紧邻相应值。
- 危险操作使用独立区域和危险色，远离普通保存。
- 警告只出现在与用户决定相关的位置，例如暂停委员会、设备接管或无效目录。
- 状态以图标、文字及颜色共同表达。按钮名称描述实际动作和必要后果。

### 12.3 响应式和可访问性

- 表单字段的标签始终可见，输入错误紧邻字段；只读信息与可编辑输入具有清晰外观差别。

### 12.4 文案标准

主要使用用户语言：`登录`、`选择委员会`、`存储文件夹`、`开始同步`、`停止同步`、`连接与存储`、`诊断日志`。配置文件、CA 证书和扫描间隔等维护信息出现在确有需要的位置。

## 13 服务端与原生实现约束

### 13.1 登录和列表

复用现有 `POST /api/v1/auth/login`、身份读取、退出与密码修改接口。原生 HTTP 客户端按现有规则携带会话 Cookie、CSRF 校验信息和正确的站点来源；服务器既有身份、访问权限和写入校验继续有效。

新增或扩展面向 Agent 的只读候选查询，返回显示和确认所需的委员会标识、名称、角色、状态、版本、当前设备及实际存储方式。权限过滤由服务端完成，最终配对再次校验。

查询放在现有 HTTP 和业务模块中。复用现有账号、委员会和绑定数据，不把列表展示结果作为授予权限的依据。

### 13.2 配对和运行

复用现有短期配对授权与设备配对流程。初次配对、转移设备、授权过期、版本冲突和权限失效按现有服务端事务边界处理。

原生界面沿用 Rust 与 Node 桥接：Rust 管理窗口和交互；Node 管理既有请求、配置、目录、恢复和同步。新增登录和选择状态应明确归属，避免多个布尔值组合出互相冲突的页面。

服务器返回配对成功、私有配置成功保存、同步实际启动和文件任务实际完成分别反馈。错误传播继续使用受控结构，页面不能展示原始服务器响应体或秘密。

### 13.3 Linux 桌面身份

应用图标、桌面入口和窗口身份统一保持 `org.quorum.ChairAgent`：

- Wayland 的 app_id 正确关联桌面入口。
- X11 的 WM_CLASS 与桌面入口的 StartupWMClass 一致。
- 应用菜单、任务切换器和窗口列表展示正确名称及图标，不显示 Unknown。
- `quorum-agent:` 链接及 `.quorum-agent` 配对文件关联有效。
- 重复唤起转交当前窗口，不启动第二个同步实例。
- 打包产物继续带齐现有 Node 运行时、桥接代码、图标和注册能力；从发布目录执行也能完成新流程。

## 15 验收标准

验收必须覆盖用户实际完成任务的过程。测试结果、浏览器证据、Linux 原生证据和真实同步证据分别记录。

### 15.1 网站与登录

- 全新用户首次打开即看到预填 `https://quorum.sramun.org` 的原生登录页。
- 网址可修改并在重启后恢复；已有安装恢复原站点。
- 正常登录、错误密码、临时密码强制修改、请求失败、证书错误、受限账号和登录过期都有明确恢复路径。
- 登录中不能重复提交；错误不是“没有委员会”；普通输入不会因重试或语言切换无故丢失。
- 密码和账号登录凭据不出现在本地设置文件、日志、诊断导出或页面普通文本中。
- 配对后结束临时账号登录，重新启动仍可依设备凭据恢复同步。
- 修改网站后旧登录状态不会用于新网站，旧设备凭据不会被直接发送到新站点。

### 15.2 委员会与暂停提醒

- 主席和所有者得到可连接候选，普通成员及无权限用户不能通过界面或伪造请求绑定。
- 已归档和正在删除的委员会不可连接。
- 暂停委员会可选择，列表明确显示 `已暂停`，选中及目录确认时明确提醒本地文件变更将在委员会恢复后同步。
- 暂停提示在中文和英文都完整可读，不被误画成离线、故障或同步停止。
- 同步主页能分别表达委员会暂停和 Agent 运行状态。
- 现有电脑名称、现有存储方式准确显示；初次连接不会暗中接管其他设备。
- 选择后发生权限撤销、归档、暂停或绑定变化时，提交使用当前服务端规则；必要时刷新并重新确认。
- 空列表、筛选无结果和加载失败互不混淆。

### 15.3 目录与配对

- 默认目录遵循系统 Documents 位置和委员会独立编号；安理会、大会、安理会顺序得到 `安理会-1`、`大会-1`、`安理会-2`。
- 两个同名但不同标识的委员会不会覆盖目录；同一个委员会在恢复时使用原目录。
- 仅浏览和取消不会创建文件夹或消耗编号。
- 系统选择器可选自定义目录，取消保留原值；目录权限、内容和身份不符合要求时给出具体反馈。
- 最后确认后自动配对、保存并启动；用户无需复制配对码或输入配置文件路径。
- 双击、慢请求和重试不会产生第二个并行同步实例。
- 授权过期、服务器状态冲突、本地保存失败和启动失败保留可恢复信息并显示正确阶段。
- 委员会没有存储时配对后自动启用主席电脑；已有存储时仍保持原存储，完成页准确表达。
- 再次启动复用原配置和目录；目录丢失不会生成一个新的空目录冒充恢复成功。

### 15.4 备用连接与网页

- 网页按钮与所操作内容位置相邻，普通按钮不会无故独占一整行。
- 网页发起配对能唤起已安装 Agent；未完成唤起时可下载配对文件继续。
- `下载配对文件` 与 `选择配对文件…` 名称一致，用户能知道其用途和获取位置。
- 有效网页授权直接进入目录确认，不重复要求账号登录及选择委员会。
- 过期或无效文件可理解、可恢复；普通配对文件与私有连接文件按各自规则校验。
- 仅发起唤起不显示配对成功，成功由服务端实际状态确认。
- 现有连接恢复、手动配对码及文件另存能力在对应的低频入口可用。

### 15.5 同步主页与设置

- 首次连接步骤只呈现当前任务；配对后默认进入同步主页。
- 同步页中运行控制、文件列表及存储位置清晰关联；设置与诊断使用独立页面。
- 开始、停止、启动中、停止中、离线、重试和单文件失败均与真实运行状态一致。
- 停止后文件行不继续显示正在上传或接收，离线时服务器缓存不假装仍为已知可用。
