# 阶段 0：当前行为基线与规则差异

本文件冻结 `002981d` 架构 checkpoint 后的 Firebase 前端行为，作为后续纵向切片的回归基线。它描述兼容目标，不把旧数据布局或客户端授权方式提升为新架构契约。

## 当前行为清单

| 领域 | 当前可观察行为 | 后续自托管约束 |
| --- | --- | --- |
| 点名 | 按席位名称排序逐一标记出席/缺席；进度刷新后保留；重置把全部席位设为缺席 | 用独立 roll call 与 attendance event 保存，不静默改写历史点名 |
| GSL | 固定 `gsl` 名单；默认每席 60 秒；当前发言计时中不能切换下一席 | 改为普通 `GENERAL` speaker list，保留暂停后切换语义 |
| 让渡 | 仅原始 GSL 发言、暂停且剩余超过 1 秒时可让渡主席/代表/问题/评论；继承时间不能再次让渡 | 服务端命令记录实际 actor、归属席位和完整动作历史 |
| 有主持核心磋商 | 默认总时长 600 秒、每席 60 秒；不足一次完整发言时自动关闭；发言结束后总计时暂停 | 服务器权威计时，队列操作在事务内串行化 |
| 自由磋商 | 使用委员会级倒计时；延长已结束或正在运行的计时器会以新时长重置 | 使用显式 timer command 和 revision，不复刻 Firebase 路径写入 |
| 动议 | 16 个现有动议类型；提出者及需要时的附议者必须出席；待裁决动议可清除；通过/未通过后保留结果与目标入口 | 每类动议用稳定 ID、规则版本、评估和裁决记录表示 |
| 动议投票 | 可由委员会设置开启；程序性动议不能弃权；公开投票以出席席位 ID 为票键 | 一席一票由数据库唯一约束保证，Chair 更正追加历史 |
| 正式表决 | 仅出席且有表决权的席位可投；支持简单多数、三分之二与忽略弃权的三分之二；存在否决席位时收齐合资格票后才公布 | ballot 创建时冻结资格、门槛与规则版本 |
| Strawpoll | 支持单选/多选、主席手工计票或链接投票；链接投票用浏览器匿名 ID | 新栈明确区分席位实名与匿名 poll，匿名结果不能转正式 ballot |
| 计时器 | 浏览器保存 elapsed/remaining/ticking，归零停止且不显示负数；关键延长使用 Firebase transaction | 服务端保存 started_at 与 remaining_at_start，不每秒写库 |
| 模板 | 账号级委员会模板引用一个国家模板；创建委员会时快照成员和国旗；被引用国家模板不可删除 | 后续切片保留稳定关联、快照和引用完整性 |
| 文件 | 链接、文本及 Storage 附件共存；删除委员会时先删附件再删委员会节点 | PostgreSQL 保存文件元数据；二进制 provider 不成为权限或业务真相 |

现有 Vitest 与 Cypress 用例继续作为旧栈回归基线。阶段 0/1 不修改页面、Firebase 初始化、Rules、Functions 或 emulator 编排。

## `Quorum Default` 与北京规则包

两个可独立校验的 fixture 位于 `packages/rule-schema/fixtures/`。阶段 0 只冻结已经能由当前代码或目标规格确认的差异，不臆造尚未经过学术审阅的参数。

| 项目 | 当前行为 / `Quorum Default` | 北京学术标准 fixture |
| --- | --- | --- |
| 默认运作模式 | `DELEGATE_OPERATED` | `CHAIR_OPERATED` |
| 点名回答 | 出席、缺席；`voting` 是席位静态“必须投票”属性 | 增加“出席并参与表决”回答；以后由 attendance snapshot 表达 |
| 代表直接申请发言 | 允许公开排队（取决于委员会设置） | 默认由主席录入 |
| 程序性、咨询性、个人特权问题 | 当前没有独立问题工作流 | 作为规则包稳定问题类型声明 |
| GSL、磋商默认时间 | 60 秒 / 600 秒，保持当前值 | 暂沿用相同值，学术审阅后以新 fixture 版本修改 |
| 多数门槛、让渡、否决等待 | 冻结当前计算和等待行为 | 未确认差异的部分继承 `Quorum Default` |

fixture 目前是契约和测试资料，不会被现有 Firebase UI 加载。北京包增加任何会中规则前必须经过审阅并发布新版本，不能改写 v1 fixture 的既有语义。

## 稳定注册表

- API 错误码：`packages/contracts/src/registry.ts` 的 `ERROR_DEFINITIONS`。
- SSE 事件名：同文件的 `COMMITTEE_EVENT_DEFINITIONS`。
- 审计动作：同文件的 `AUDIT_ACTION_DEFINITIONS`。

注册表只确定稳定名字、默认状态码或受众；具体授权、事务和 payload 在相应业务切片实现。公开值发布后不得原地改义。
