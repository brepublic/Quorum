# 决议与修正案选择已发布文件：实施方案

日期：2026-09-21。状态：尚未实施文件接入改造；按钮样式统一已实施。用户已确定：审核赋予的正式名称在委员会内唯一；新上传文件审核时使用已有正式名称，经二次确认后成为该文件的新版本；决议和修正案引用最新版。不鼓励直接操作存储文件夹。

## 1. 目标与边界

决议和修正案保留“文本 / 文件”两种正文形式。选择“文件”时，只能引用本委员会文件系统中已发布的文件；页面不再提供本地选文件、上传、提交审核、批准发布文件的入口。

这里“已公开”对应文件状态 `PUBLISHED`，不是把私有委员会的文件公开到互联网。沿用现有委员会访问权限、文书编辑权限、展示动议和表决规则。文书禁止改选正文时，已引用的同一文件仍按用户要求跟随最新版；文件更新不自动改变文书的表决结果。文件已发布不等于决议或修正案已经展示、通过或纳入。

上传和审核集中在现有文件模块：上传 → 持久保存 → 主席审核 → 已发布 → 文书选择引用。不创建另一套附件、存储服务或依赖，也不复制文件字节。

不额外限制上传者或会期；现有三种文件类型没有独立的修正案类型，首版允许选择所有已发布文件，并显示类型供主席判断。不擅自增加类型或把工作文件排除在外。

## 2. 已核实的现状

- `src/pages/self-hosted/ProceedingsPanel.tsx` 的 `AmendmentCard` 和 `DocumentWorkspace` 已使用 `listFiles`、`createDocumentVersion` 和现有存储上传接口。问题是入口重复，两个选择器只排除 `DELETED`，并未限定 `PUBLISHED`。
- `server/src/modules/stage5/service.ts` 的 `createDocumentVersion` 校验同一委员会和未删除文件，但目前允许未发布文件作为正文。只改前端筛选不能形成完整约束。
- `document_versions.content_file_entry_id` 已保存文件引用；现有接口足以完成“选择文件并创建文书新版本”，无需为基础选择流程新增表或接口。
- Stage 4 工作区快照和 Stage 5 文书返回值都通过 `file_entries.current_version_id` 读取文件；文书没有固定文件的具体历史版本。
- 网页删除和主席客户端删除都会清理文件字节，目前没有文书引用保护。更换同一文件条目的内容也会影响已引用它的文书。
- 当前文书下载链接直接访问下载地址；Chair Agent 缓存未就绪时，应在后续接入改造中复用现有“准备下载 → 查询准备状态 → 下载”流程。当前按钮样式修复不改变下载逻辑。

## 3. 页面交互

1. 切换到“文件”：读取本委员会文件列表，筛选 `status === 'PUBLISHED'`。加载中、加载失败和没有已发布文件分别展示，不能把请求失败显示为“没有文件”。
2. 选择器显示委员会内唯一的正式名称；必要时显示已有类型、来源、原始文件名。仅在需要时提供搜索，不新增第二套文件管理界面。
3. 选中后点击“使用此文件”，复用 `createDocumentVersion`。保存成功后才更新当前正文；失败保留原引用和候选选择，允许重试。提交中禁用重复提交。
4. 当前引用显示文件名、类型及下载按钮。下载使用统一蓝色、向下箭头样式。可编辑时允许选择另一文件；表决中或终态文书按现有规则禁止改选文件，但同一文件记录经确认覆盖后仍跟随最新版。
5. 没有已发布文件时显示短提示和权限允许的文件模块入口；不在文书页重新放置上传或审核控件。匿名读者不显示编辑入口。
6. 接收现有委员会事件后刷新候选列表；选择失效时清除候选、禁止提交，但不擅自删除已经保存的正文引用。
7. 保留文本正文的现有保存方式。切换显示模式本身不清空已保存正文，也不绕过现有权限或版本检查。

## 4. 服务端约束

- 在 `createDocumentVersion` 同一事务中确认：操作者能编辑文书、委员会有效、文书版本未过期且未冻结、文件属于该委员会、文件状态为 `PUBLISHED`。
- 新选入的文件若在提交时已删除或不再是已发布状态，拒绝此次绑定并给出可操作的结构化错误；始终引用所选文件记录的最新版，不固定文件历史版本。
- 对授权校验、文件状态检查及引用写入使用一致的锁顺序，覆盖绑定与文件覆盖/删除并发情况。现有 `FOR KEY SHARE` 不应被当作阻止普通状态更新的保证。
- 保留正文文本与文件互斥规则，以及文书 revision、审计、事件和历史版本。继续在展示、进入表决等现有入口检查正文可用性。
- “只能选择已发布文件”不等于修改文件模块的权限：`listFiles` 在总览中仍需按原有权限展示待审核等状态。

## 5. 已确定的正式名称、版本更新与覆盖确认

**审核给予的正式名称是委员会内唯一的业务标识。同名的新提交在审核批准并二次确认后，成为已有文件的新版本；所有引用该文件的决议和修正案随之使用最新版。** 不固定历史文件版本。

### 审核交互

1. 上传仍产生独立的待审核提交；原始文件名相同不会立即覆盖已发布文件。未审核的上传名称不占用正式名称。
2. 编辑审核名称时检查本委员会已有正式名称；命中时在输入框旁提示“该名称已存在，批准后将更新已有文件。”名称检查必须跟随最新输入，不能显示较早请求的结果。
3. 点击批准：名称尚未使用则正常发布；名称已存在则弹出居中二次确认，显示目标正式名称，说明“将替换此文件的当前版本，引用它的决议和修正案将同步更新。”确认按钮为“确认替换并发布”。输入时的提示不能代替二次确认。
4. 取消确认保留待审核提交，原文件和文书引用不变。确认成功后，新内容成为已有文件的已发布最新版；不再要求同一内容重复审核。新提交未批准或被驳回时，原已发布版本继续可用。
5. 引导用户通过网页上传和审核更新文件，不把直接修改存储文件夹作为推荐流程，也不再要求另设“替换文件”上传入口。

### 服务端与存储实现

- 正式名称用于定位委员会内的业务文件；内部继续用现有记录 ID 维护稳定引用。同名批准保留目标 ID，追加文件版本并更新当前版本，因此已有文书无需逐条改绑。
- 名称唯一性只针对正式文件，不能直接对所有待审核记录的 `logical_name` 加唯一约束。复用现有文件记录和版本结构，实施时明确正式名称的保存与唯一约束；输入提示、批准检查和数据库必须采用同一名称比较规则，不擅自引入模糊匹配。大小写、首尾空格及已删除名称是否可复用需在实施细化时明确。
- 二次确认绑定新提交及其 revision/内容、正式名称、目标记录和目标 revision；提交后修改名称或内容必须重新确认。服务端在批准事务中重查权限、来源和目标状态；目标已变化或被删除时拒绝旧确认，刷新后重新确认。并发批准不能产生同名的两条正式记录。
- 替换发生在审核批准阶段，不在上传持久化阶段提前覆盖。复用已验证的文件字节和现有存储能力；原提交的上传者、类型、提交时间、审核结果和版本来源必须可追溯，不能简单删除提交记录或让它作为第二条同名正式文件出现。代表只能看到自己有权读取的提交信息。
- 当前存储直接覆盖会重设 `PENDING_REVIEW`，不能直接套用该流程作为最终审核结果。新的“确认替换并发布”需在一次事务中完成版本关联、发布、原提交审核结果、事件及审计；任一步失败则保持原正式版本。三种存储位置都需验证缓存、版本字节归属及清理任务不会误删仍被使用的内容。
- 不鼓励操作文件夹不等于授权删除同步功能。现有主席客户端自动更新路径仍需检查：不得绕过正式名称唯一规则、审核和二次确认；其具体收口方式在实施前细化，不扩展为新的文件夹管理界面。
- 文件删除沿用现有规则，本次没有授权新增“被引用就禁止删除”的限制；文书对已删除引用明确显示不可用。委员会整体永久删除流程不变。

改造前机制（并非目标行为）：网页新上传创建新记录；审核更名只修改该记录的展示名；存储内部只有明确携带现有 `fileEntryId` 和 `baseRevision` 才追加该记录的新版本。主席客户端对同名的其他记录返回名称冲突，不按名字合并；对已跟踪路径的内容改变则按其已知记录 ID 提交新版本。正常的这类客户端更新目前没有统一二次确认。

## 6. 已有数据

- 已绑定且仍已发布的文件继续引用，不重复上传、不复制、不改名。
- 已绑定但未发布的文件不自动批准：保留现有记录，显示真实状态，指向现有文件审核流程；发布后可继续使用，或由有权限者换成已发布文件。
- 已被删除的文件不得伪装成空文本正文。当前快照会把这种引用转成 `null`；实施时需要保留“存在引用但文件不可用”的明确表示，更新契约及两处快照映射，不恢复不存在的字节。
- 已有引用继续跟随当前文件记录的最新版，不回填固定历史版本，也不补造原表决时的文件内容。
- 建立名称唯一约束前检查已有正式文件重名；若存在，列出冲突及各自引用供处理，不凭时间顺序自动合并或丢弃内容。

## 8. 验收用例

- 文件列表同时存在已发布、待审核、驳回、已删除记录时，两个选择器只出现可选的已发布文件；不出现其他委员会文件。
- 绑定已发布文件成功；空选择不可提交；重复点击不重复创建版本；保存失败保留原正文。
- 构造接口请求绑定未发布、已删除或跨委员会文件必须失败；无权限用户不可绕过浏览器。
- 同名原始文件上传只创建待审核提交；正式名称编辑命中现有名称时及时提示，不跨委员会匹配，较早查询结果不覆盖较新输入的结果。
- 同名审核批准必须二次确认；取消或驳回后原版本仍可用，确认后只有一条对应正式文件且所有旧引用得到最新版。新旧提交来源及审核历史均可追溯。
- 过期确认、确认后改名/内容变化、并发批准同名文件和客户端绕过确认必须被拒绝或要求重新确认，不能静默覆盖或生成重复正式名称。
- 选择后文件状态变化、并发绑定与删除/覆盖、文书 revision 冲突均得到明确结果；覆盖成功后所有相关文书跟随最新版，并按文件当前状态处理访问。
- 文书表决中及终态不允许改选正文引用，但已引用文件仍跟随经确认覆盖后的最新版；文件更新不自动展示决议/修正案，也不改变其结果。
- SERVER_VOLUME、S3、CHAIR_AGENT 复用现有存储能力；Chair Agent 在线缓存回填、离线缓存命中和不可用状态分别验收。
- 已绑定的不可用文件、加载错误、空列表、长名称、中文/英文以及窄屏布局分别检查。
- 更新 `CommitteeWorkspaceRoutes.test.tsx` 中原“上传并绑定”“页面内发布附件”的用例，替换为已发布文件选择流程；保留文件模块的上传审核测试。
- 数据库测试使用隔离临时库；未配置测试数据库时明确跳过。真实 S3/Chair Agent 未执行时单独说明，不能由模拟测试替代。
